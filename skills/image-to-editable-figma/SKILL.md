# 图片转可编辑 Figma

## 设计判断

开始时先写一行：

`将其理解为：面向 <受众> 的 <页面类型>，采用 <视觉语言>，接近 <设计系统或审美家族>。DESIGN_VARIANCE <1–10> / MOTION_INTENSITY <1–10> / VISUAL_DENSITY <1–10>。`

从参考图推断真实视觉语言。保留原图的配色、字体、纹理、间距、对比度和插画笔触，不要套用无关的 UI 套件或预设风格。

## 并行 Agent 工作流（默认）

复杂截图默认采用“分析并行、资产并行、单点编排”的流程，不由一个 Agent 串行完成全部工作。主 Agent 负责分派、合并台账和最终验收；子 Agent 不直接改动最终 Figma 画板。

1. **布局审查 Agent**：读取原图，输出完整的视觉与结构测量台账，而不只是几何：
   - 画布与坐标：原始像素尺寸、设备安全区、页面边界、区域层级、滚动/固定区域和裁切范围；
   - 几何规范：网格、列/行、间距、内外边距、对齐、尺寸、圆角、描边、阴影、透明度和叠放顺序；
   - 色彩与材质：背景/前景/强调色的取样值、渐变、明暗层级、纸张纹理、噪点、透明叠加和颜色对比关系；
   - 文字规范：文字内容、字体候选、字重、字号、行高、字距、颜色、基线、文本框宽高、换行方式和语言方向；
   - 元素识别：每个图标、头像、插画、贴纸、装饰图案、按钮视觉和状态标记，记录它是结构层、矢量层还是 Image Two 素材；
   - 行为与状态：默认/选中/禁用/输入中/发送中等可见状态、组件重复关系、可替换属性和交互安全区；
   - 复刻风险：透明边缘、低清素材、遮挡关系、相似颜色、字体缺失、无法确定的图层归属和测量误差。
   每个字段必须标注 `measured`（从原图测得）、`inferred`（根据上下文推断）或 `unknown`（待确认），并提交视口、区域边界、文本框几何、颜色字典、材质清单、重复组件清单和不确定项；它只提交台账，不直接修改最终 Figma 画板。
2. **视觉与素材审查 Agent**：逐项标记背景、纹理、头像、插画、贴纸、图标、装饰图案和按钮视觉，区分“原生结构”与“必须使用 Image Two 的位图/SVG 素材”，并输出素材规格、透明度、裁切框、命名和状态表。
3. **Image Two 资产 Agent（可并行多个）**：按素材状态表批量生成或提取资产；每个资产单独保存源文件、预览、尺寸、透明通道、提示词/来源和哈希。生成可以持续进行，但必须有明确的验收规格，不能无目的重复生成或把生成文字当作可编辑文本。
4. **Figma 编排 Agent**：确认 Figwright 当前文件、页面和画板身份，先创建 token、组件母版和素材库分区，再按布局台账创建区域组件与实例，最后绑定已验收的 Image Two 素材。它是唯一允许写入最终屏幕的 Agent。
5. **视觉 QA Agent**：在编排 Agent 完成一个可运行版本后，对同尺寸截图逐区对照，报告最大差异及对应节点 ID；必要时只提出修复指令，由编排 Agent 顺序执行。

子 Agent 之间通过结构化产物通信：`layout.json`、`asset-manifest.json`、`component-plan.json`、`qa-diff.json`。主 Agent 合并前检查版本号、画布比例、坐标系和素材哈希，发现冲突时以原图测量台账为准。独立任务应并行启动；依赖前置产物的任务才等待，不要让全部流程串行阻塞。

为了缩短耗时：先一次性完成读图与资产清单，再批量生成 Image Two 素材；Figma 写入采用批处理创建和批处理属性设置；每个阶段只做一次汇总读取，避免逐节点往返。失败只重试失败的素材或操作，不重跑整条流水线。

## 素材与源图审计

1. 按原始像素尺寸检查参考图，记录画布尺寸、安全区、区域边界、重复间距、颜色、字体层级、圆角、阴影和图片区域。
2. 先读取随附的 HTML、CSS、SVG、素材目录或设计说明，再开始猜测。确认真实字体、图标和插画资产。
3. 区分附件中可见的说明和用户请求；用户请求优先。
4. 创建简短的、从参考图推导出的组件清单。只列出实际存在的区域、重复项、控件、状态、文本/图标层和素材，不要套固定模板。
5. 创建几何台账：视口、区域边界、文本基线、文本宽度、行高、间距、圆角、阴影、裁切框和安全区。所有坐标必须使用同一套原始像素比例。

## 高保真策略

- 先匹配几何，再匹配样式。创建与源图完全相同尺寸的固定画板，使用测量值，不使用目测值。
- 每个有意义的区域都要成为组件；重复区域必须有组件母版和实例。
- 组件母版放在 `02｜组件库与素材`，主页面放在 `01｜还原稿与组件`。
- 为参考图中真实存在的重复状态建立变体，不发明无用状态轴。
- 暴露 TEXT、BOOLEAN 和 INSTANCE_SWAP 属性，使文案、可选层和素材可编辑、可替换。
- 优先使用原生 Figma 文本、矩形、椭圆、矢量、自动布局和组件实例；不要把完整截图作为可见 UI 背景。

## 组件库布局与实例纪律

- 创建组件母版后必须设置明确的 `x/y` 位置。Figma 默认把新节点放在页面原点，未定位的母版会全部重叠。
- 在 `02｜组件库与素材` 建立可见网格或分区框，为每个母版设置稳定位置、间距和语义名称。
- 主页面中的重复区域必须使用组件实例，不要重新绘制一套互不关联的基础图形。
- 创建完母版和实例后检查图层树：每个重复视觉必须能找到一个母版和至少一个实例。
- 消息列表、气泡文本、快捷按钮行、输入框内容和底部导航使用自动布局；只有测量过的固定艺术覆盖层才使用绝对定位。

## 文件身份与恢复已有成果

- 每次开始、恢复上下文或切换连接工具后，先读取当前文档与目标节点；核对文件名、可用的文件 key/URL、页面 ID/名称、最终画板 ID、组件库位置。不能把“工具连接成功”当作连接了正确文件的证据。
- 用户提供已有优秀版本时，先定位并读取其结构与素材引用，优先在该版本上修复。未经核对，不得在另一个文件或临时画板重建后声称延续了原成果。
- `fileKey: null` 仅代表接口没有返回文件 key；不能据此断言文件未保存、没有云端链接或位于某个项目。通过可用的文档信息或浏览器地址验证；无法验证时如实说明。
- 台账记录工具名称、最后核验时间、目标文件和页面、最终屏幕、母版及实例 ID。工具切换后重新核对 ID，不沿用另一个文档的 ID。

## 替换、层级与遮挡纪律

- 主屏幕保持“屏幕 → 区域实例 → 控件/素材实例 → 文本、矢量或图片”的层级。组件母版和素材板放在画板外的组件库，不把母版与其实例叠放在同一位置。
- 创建区域容器时立即确认父子关系；不能后创建一个有不透明填充的空容器，覆盖原有标题、气泡或内容。移动节点时区分页面坐标与父容器局部坐标，并在移动后读取实际边界。
- 替换前记录旧节点、所属父级、局部位置、尺寸、裁切和层级顺序。替换后确认旧视觉已移除、同一位置只剩一个有效实例，避免文字、时间、头像、导航或输入框重复渲染。
- 导入图片后先检查原始尺寸、透明通道、边缘、缩放模式和实际清晰度，再封装素材组件。不得把透明图直接转成带黑底的 JPEG，也不得把低分辨率缩略图放大后作为最终素材。
- 图片进入素材组件后，再通过实例放入区域；检查父组件填充、裁切和实例覆盖值，不能只凭 import 成功就认定替换完成。
- 每批修改后读取节点树并导出截图。发现内容消失、灰块、白块、重复字或位置漂移时，暂停继续叠加节点，先定位具体遮挡层、重复层、字体或裁切原因。

## 字体与几何锁定

- 在创建文本前确认并锁定真实字体家族和样式。找不到原字体时必须记录回退字体，并重新校准所有受影响的文本框，不能假设回退字体的字宽和行高相同。
- 文本换行与参考图不一致时，先修正字体、文本宽度、行高或文案，再调整后续坐标。
- 不要使用固定的、凭感觉写出的下一个 `y` 坐标来连接可换行文本。用自动布局或实际文本边界，避免字体变化造成气泡、时间、插画和控件重叠。
- 输入框和底部导航属于固定安全区；聊天内容必须在其上方结束，不能侵入操作区域。

## 位图与 Image Two 素材

- 所有视觉素材默认统一由 Image Two 生成或提取：头像、插画、背景纹理、纸张肌理、装饰图案、贴纸、手绘图标、按钮中的视觉符号、插图化 UI 素材和其他非结构性图形都必须走 Image Two 流程。
- 只有文字、容器、布局、间距、圆角、状态、交互区域和需要精确编辑的 UI 结构保留为原生 Figma 图层；不要用 Image Two 生成文字或需要像素精确交互的几何容器。
- 先尝试从原图干净提取；无法直接提取时，必须调用 Image Two 生成对应素材，并保留主题、轮廓、构图、色板、线质、纹理、比例和透明度。
- 每个 Image Two 素材都要作为独立可替换图片组件导入，并通过 INSTANCE_SWAP 或明确的素材实例放入主屏幕。
- 不得用 emoji、系统符号、通用图标库、库存插画、CSS 图案或无关模型图替代 Image Two 素材。
- Image Two 不可用或失败时，才允许使用其他图像模型作为回退，并在交付中明确说明具体素材和回退原因。
- 插画笔触、背景纹理和手绘细节仍是位图像素时必须如实说明，不能声称已逐笔矢量化。

## Figma 执行顺序

在启动写入前，主 Agent 必须收到布局台账、素材清单和组件计划；缺少任一产物时先补齐，不得边猜边画。Figwright 编排阶段使用单一坐标系和统一父级，创建后立即按区域截图，而不是等所有层叠加完才发现结构错误。

1. 检查目标文件、当前页面、组件、变量、样式和字体。
2. 先创建 token 和组件母版，再逐步创建实例；每次写入都返回创建或修改的节点 ID。
3. 按顺序构建：画面外壳 → 素材母版 → 原子组件 → 区域组件 → 区域实例 → 最终屏幕。
4. 每次修改文本前加载字体，并等待所有异步 Figma 调用完成。
5. 相关内容使用自动布局；参考屏幕使用固定尺寸和测量过的区域几何。
6. 绝不猜测节点 ID；维护页面 ID、母版 ID、变体 ID、变量、图片哈希和最终屏幕 ID 的状态台账。
7. 不删除用户已有节点，只移动或删除本次创建且已确认 ID 的节点。

## 持续执行与停止协议

- “开始重建”即创建一个持续任务，不能因单次工具调用结束、短暂超时、上下文压缩、模型切换或一两分钟无新截图而自行停止。只有满足本节停止条件，或确实遇到连续三次相同且无法绕过的外部阻塞，才可以结束。
- 主 Agent 维护 `rebuild-status.json`（阶段、当前批次、已完成清单、失败清单、下一动作、最后证据时间）和验收清单。每个阶段必须有明确的进入条件、产物和退出条件：读图、资产、组件、编排、QA、修复、最终验收。
- 长任务每完成一个批次或每隔不超过 60 秒发送一次简短进度，说明“已完成什么、证据是什么、下一步是什么”。进度消息不是完成信号；工具超时后重新读取同一目标状态，确认任务是否实际执行，不能未经核实重跑整条流程。
- 任一阶段未达到退出条件时，继续执行下一项最小安全动作：补读台账、定位节点、重试单个失败操作、截图复核或修复差异。不得用“基本完成”“效果差不多”“已创建节点数量”替代证据。
- 发生错误时记录错误类型、操作、目标 ID 和重试次数。先重试幂等的单项操作，再切换等价安全路径；连续三次相同外部错误仍无法推进时，报告具体阻塞和已尝试的替代方案，但保持任务未完成状态，不得伪造通过。
- 停止前必须逐项勾选最终验收门禁：关闭参考底图仍能正确显示；同尺寸截图完成至少两轮差异修复；节点树、组件母版/实例、素材清单和可编辑性均有证据；文件/页面/画板身份已核实；无重叠、乱码、占位或安全区侵入。任何一项缺失都必须继续工作。
- 只有在所有验收项均有当前证据并完成最终截图后，才允许发送完成答复或将任务标记为 complete；否则明确标记为进行中。

## 验证门禁

每个主要区域完成后都要检查结构并截图。交付前必须确认：

- 画板尺寸、区域位置、颜色和字体层级与原图一致；
- 没有把完整截图作为可见 UI 背景；
- 主屏幕中确实使用了区域组件实例；
- 文本、时间、标签、导航和控件仍可编辑；
- 艺术素材可独立替换，且不包含邻近文字；
- 组件库页面容易找到，母版没有重叠在页面原点；
- 没有文本裁切、重叠或被图片遮挡；
- 字体是精确匹配，或已记录回退字体并完成指标校准；
- 输入框和底部导航保留原图安全区；
- 已完成同尺寸原图与 Figma 截图的对照检查；
- 交付信息包含 Figma 链接、屏幕节点、组件库页面、可编辑范围和位图限制。

对照时优先修复最大差异：素材身份与裁切、字体与换行、区域位置、颜色，最后才是微小间距。

## 防止底图伪装与完成审计

- 完整参考截图只能放在独立的参考画板中。不得置于交付屏幕的顶部或底部来补足缺失内容；不得隐藏错误组件、露出参考截图，再以截图相似为由宣告完成。
- 隐藏的可编辑层加上一张可见参考截图，不等于可编辑复刻。验收必须针对实际可见的组件实例，而不是图层树里仅仅存在的节点。
- 验收前关闭所有完整参考图和对照覆盖层，在此状态下导出最终屏幕。若关闭后标题、气泡、插画、导航等消失或效果崩溃，直接判定未完成。
- 至少完成两轮“同尺寸截图 → 记录具体差异 → 修复 → 重新截图”；记录必须对应真实节点和可观察问题。工具返回 ok 只证明命令执行，不能代替效果验证。
- 分别验证视觉和可编辑性：检查文字、时间、按钮、输入框、导航等确实是可见文本/结构层；检查重复项的母版与实例关系、素材独立替换能力、组件库分区和命名。两类证据缺一不可。
- 在可丢弃的验证副本上修改一处文案、替换一个素材实例，确认仅预期区域变化且无底图残留；完成后清理本次验证副本，不修改用户已有成果。
- 任一关键区域缺失、重叠、占位、素材未替换、依赖整图显示，或文件定位未核实，都不能宣告最终交付。不能因耗时很长、已创建许多节点或工具调用成功而降低标准。
- 若先前错误地宣告完成，应明确纠正完成状态并说明尚未满足的要求。不能继续沿用“已完成”“基本 1:1”“全部组件化”等没有证据支持的描述。
- 故障解释区分“截图可见现象”“节点树/操作记录证实的原因”和“尚待验证的推测”。不能仅凭画面不同就断言属于另一个文件。

## 推荐命名

使用 `区域 / ...`、`控件 / ...`、`卡片 / ...`、`列表项 / ...`、`图标 / ...` 和 `素材 / ...` 等语义名称。名称应描述当前产品中的真实作用，不要沿用其他项目的名称。

## 交付语言

只有在截图验证通过后，才能称为“高保真可编辑组件稿”。明确说明哪些是原生图层、哪些是组件实例、哪些仍是位图。

## 失败停止条件

出现以下任一情况时，视为复刻未完成，必须先诊断结构、字体、素材和几何原因：

- 组件母版重叠、全部位于页面原点或无法作为独立图层找到；
- 主页面只是平铺基础图形，没有重复区域的组件实例；
- 使用了 emoji、系统字形或通用图标替代可识别素材；
- 背景、纹理、装饰图案、手绘图标或其他视觉素材没有经过 Image Two，且没有记录明确的回退原因；
- 文本换行、字体指标或行高导致邻近内容移动；
- 输入框、导航、插画或消息气泡互相重叠，或侵犯原图安全区；
- 没有完成最终同尺寸截图对照。
